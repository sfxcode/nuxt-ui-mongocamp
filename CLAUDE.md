# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

A Nuxt module (`nuxt-ui-mongocamp`) that wraps `@sfxcode/nuxt-mongocamp-server` with ready-made UI components, composables, and a runtime plugin. Consumers add the module to their Nuxt app and get MongoCamp auth, user/role management, and collection access out of the box.

**Server baseline: MongoCamp server 1.6.3+** (dependency `@sfxcode/nuxt-mongocamp-server` ^1.6.3). There is deliberately no compatibility code for older servers (decided 2026-11-02) — don't add workarounds for 1.5.x/1.6.0–1.6.2 behaviour; the known *current* server limits (Lucene open ranges, `>=`, `_exists_`, negated `AND` groups) are still worked around.

## Commands

```bash
# Install dependencies
pnpm install

# Build stubs + prepare the playground (run once after clone, and after module source changes)
pnpm run dev:prepare

# Start playground dev server (hot-reloads module changes)
pnpm run dev

# Lint
pnpm run lint

# Run tests (Vitest + @nuxt/test-utils e2e against the fixture app)
pnpm run test
pnpm run test:watch

# Type-check
pnpm run test:types

# Build for publishing
pnpm run prepack
```

The playground reads `playground/.env` for `MONGOCAMP_URL`, `MONGOCAMP_ADMIN_USER`, and `MONGOCAMP_ADMIN_PASSWORD`. Optional vars demo server proxy auth mode: `MONGOCAMP_API_KEY`, `MONGOCAMP_USE_SERVER_PROXY=true`, and `MONGOCAMP_PROXY_SHARED_SECRET` (activates the example guard hook in `playground/server/plugins/mongocamp-proxy-guard.ts`) — see `docs/guide/server-proxy-auth.md`.

## Architecture

### Module entry — `src/module.ts`

Declares `moduleDependencies` for `@nuxt/ui`, `unocss-nuxt-ui`, `@formkit/nuxt`, `@sfxcode/nuxt-ui-formkit`, `@sfxcode/nuxt-mongocamp-server`, and `@nuxtjs/i18n` (see [Internationalization](#internationalization--srcruntimelocales) below). On setup it registers:
- The runtime plugin (`src/runtime/plugin.ts`)
- All components in `src/runtime/components/` (auto-imported)
- All composables in `src/runtime/composables/` (auto-imported)
- The server proxy catch-all route (`src/runtime/server/handlers/mongocampProxy.ts`), unconditionally — like the auth middleware below, it's always registered but internally gated by a runtime option (`useServerProxy`, default `false`)

Also warns at build time (via `consola`) if `useServerProxy` and `useGlobalAuthMiddleware` are both enabled — server proxy mode has no login, so `securedRouteParts`/`managementRouteParts`/`adminRouteParts` could never unlock.

### Runtime plugin — `src/runtime/plugin.ts`

Runs on app boot. Fetches the MongoCamp server version via `systemApi.version()` and provides it as `$mongocampVersion`. If the module's `useGlobalAuthMiddleware` option is `true` (default `false` — opt-in), registers a global `global-auth` route middleware built on `useMongocampRoles()`:
- Gates routes by glob pattern against `securedRouteParts` (requires login), `managementRouteParts` (requires manager/admin), and `adminRouteParts` (requires admin) — all configured under the module's own `nuxtUiMongocamp` key, all defaulting to `[]` (nothing protected until configured)
- Optional `session-guard` middleware (module option `sessionGuard`, default `false`; registered before `global-auth`, never in proxy mode): an expired token (`exp` only, `tokenExpiryState`; unreadable ⇒ untouched) is cleared via `logout()` on any route and the user is sent to `loginPath` (module option, default `'/'`, always allowed) only if the route needs a login afterwards — logic in `utils/sessionGuard.ts`
- Awaits `logout()` on `logoutPath` (module option, default `'/logout'`), then redirects to `logoutRedirectPath` (module option, default `'/'`)
- Redirects to `notAllowedPath` (module option, default `'/'`) on any other disallowed route
- Both redirect targets are always themselves treated as allowed, so neither can ever loop

See `src/module.ts`'s `ModuleOptions` for the full option list and `docs/guide/route-protection.md` for behavior details.

### Server proxy mode — `src/runtime/server/handlers/mongocampProxy.ts`

A second, optional auth mode for consumers who only have a MongoCamp api key and never want it reaching the browser (`mongocamp.apiKey`, the dependency's own config key — stored server-side only). When `useServerProxy` is `true`:
- A catch-all route at `serverProxyPath` (default `/api/_mongocamp`) reverse-proxies any request to the real MongoCamp server via `h3`'s `proxyRequest`, injecting the api key as an `X-AUTH-APIKEY` header and neutralizing any caller-supplied `Authorization` header
- Before forwarding, it calls a Nitro hook (`mongocamp-proxy:authorize`, via `useNitroApp().hooks.callHook(...)`) that a consumer can tap from their own `server/plugins/*.ts` to reject unauthorized callers — unregistered, it's a no-op (the route is otherwise unguarded, since reaching it grants the api key's full power)
- `useMongocampClientApi()` (composable, see below) picks this mode or the default session mode per-call, so every built-in composable/component works unmodified in either mode

See `docs/guide/server-proxy-auth.md` for the full guide, including the guard-hook contract and example.

### Composables — `src/runtime/composables/`

Kept in sync with `docs/composables/index.md` (the canonical, per-composable-documented list) — check there first if this list looks stale.

- **`useMongocampAdmin`** — wraps `adminApi` and `collectionApi` from `useMongocampApi()` for user and role CRUD (`listUsers`, `addUser`, `deleteUser`, `updateUserRoles`, `updateUserPassword`, `listRoles`, `addRole`, `updateRole`, `deleteRole`, `listCollections`, `clearCollection`, `deleteCollection`, `getJsonSchema`, `getUser`, `getRole`, `regenerateUserApiKey` (returns the plain key; the misspelled client method `gnerateNewApiKeyForUser` is called only there) — the last six with a 15 s timeout; clear/delete are irreversible and unguarded, so callers put them behind `MongocampConfirmByName` and `isProtectedCollection`)
- **`useMongocampCollection`** — reactive state for paginated collection queries: `filter`, `sort`, `projection`, `pagination` (pageIndex + pageSize), `total`
- **`useMongocampDocument`** — helpers for document-level operations: `ensureMetaData` (stamps `createdBy`/`updatedBy`/timestamps from the logged-in user) and `updateFromPartial`
- **`useMongocampSchema`** — exports `useJsonSchema()` with `schemaToColumnDefinition(definition, fields)` for mapping a `JsonSchemaDefinition` to UTable column configs; sorts `_id` first, then id-containing fields, then others; detects `date-time` and `number` types
- **`useMongocampBucket`** — GridFS bucket detection, file-id resolution, upload/download/delete/rename, `uploadFiles(bucket, files, { signal, onProgress })` → `{ uploaded, failed, aborted }`, `fetchFileBlob` (no download); `listFiles` refuses a filter over 1800 URL-encoded characters (the server's 414 has no CORS headers — `utils/requestLimits.ts`)
- **`useMongocampIndex`** — create/list/delete MongoDB indexes (standard, unique, text, expiring) plus `createIndexForField(collection, field, ascending = true)` (plain single-field index, 15 s timeout)
- **`useMongocampJobs`** — list/register/update/execute/delete scheduled background jobs
- **`useMongocampAccount`** — account self-service: profile, password change, API key regeneration
- **`useMongocampSystem`** — read-only database viewer (list, per-database info, collections) plus the read-only server settings: `getCluster()` (members, falls back to `[coordinator]`), `getSettings() (plugin lists only), `listConfigurations()` / `getConfig(key)` (rows already masked); every call has a 15 s timeout; `shutdown`/`updateConfiguration`/`deleteDatabase` are deliberately not exposed
- **`useMongocampFilterBuilder`** — pure `buildFilterQuery(group, fieldTypes)` / `buildCondition`: filter rows (field, operator, value) → one Lucene string (a group-level `negate` flag excludes the matches, written with De Morgan); operators depend on field type, incomplete rows are skipped, range bounds only accept plain numbers/ISO dates (the query helpers don't escape them); operator set is limited to what a real server was verified to handle (`_id` is the `objectId` type with only `equals`/`notEquals`/`oneOf` on 24-hex ids — wildcards on it match nothing; nothing for arrays/objects/boolean existence); it delegates ranges and existence to `useMongocampQuery`, which closes open ranges with far bounds, widens bare dates and writes `exists` per value type because the server has no working `_exists_`/`[x TO *]` — see its docs page
- **`useMongocampExport`** — `rowsToCsv` / `downloadTextFile` for exporting the rows already on screen (used by `MongocampCollectionData`'s export menu)
- **`useMongocampBulkDelete`** — `runBulkDelete(items, remove, concurrency, removeMany?)`: limited-concurrency deletes returning `{ deleted, failed }` per item; optional `removeMany` (`run`, `canHandle`, `chunkSize`) deletes in chunks with one request each and re-deletes a failed/short chunk one by one (never calls `run` with an empty chunk — an empty filter wipes a collection); both runners take `{ signal, onProgress }` (abort stops before the next request; `notAttempted` lists the untouched items, absent otherwise) — used for "select all matching" in `MongocampCollectionData` (ids via `useMongocampFetchAll` with projection `_id`, ≤ 10 000, chunks of 100, collection name typed; ids are a snapshot, never atomic)
- **`useMongocampImport`** — `importRows(collection, rows, { batchSize, stampMetadata, signal, onProgress })`: sequential `documentApi.insertMany` batches, per-batch failure report (`mayBePartial` is false only for a 400), 60 s timeout per batch; the parsing/validation lives in `utils/importRows.ts` + `importPipeline.ts` (`prepareImport`), batching in `utils/batchInsert.ts`, id chunking in `utils/bulkEdit.ts` (`runBulkUpdate`, `buildIdFilter`), `utils/objectId.ts`; server behaviour in `brain/project/mongocamp-bulk-endpoints-server-behavior.md`
- **`useMongocampAggregation`** — `runAggregation(collection, pipeline, { page, rowsPerPage })` (`aggregateRaw`, pagination headers, `allowDiskUse: false`, throws `ForbiddenPipelineError` before any request (`{ allowStatsStages: true }` lets internal calls use `$collStats`/`$indexStats` only, and strips `host`/`ns` from the rows — `stripServerFields`); an empty result is a plain `200 []` since server 1.6.1 — the old `500 "Index 0 out of bounds…"` workaround is gone), `listDistinct` (scalars only, drops `null`; feeds the filter builder's value suggestions), `sampleDocuments` (`$sample`, one page), `describeAggregationError` (only MongoDB's own message — the raw error contains the database host:port). Helpers in `utils/aggregationPipeline.ts` (`buildPipeline`, `parsePipeline`, `findForbidden`, `validateStages`, …), `aggregationErrors.ts`, `aggregationResult.ts`, `analyzeSamples.ts`, `filterSuggestions.ts`; server behaviour in `brain/project/mongocamp-aggregation-server-behavior.md`
- **`useMongocampError`** — `describeError(e)` maps API errors (`FetchError` → network, 401, 403, other) to i18n messages for `MongocampErrorAlert`; `describeServerError(e, fallbackKey?)` (async) also reads the `{ code, msg }` body via `utils/serverError.ts` (`readServerError`: code `4031` ⇒ `notAllowed` with the operator, 400 ⇒ `invalid`, other ≥ 400 ⇒ the server's message; database addresses always stripped) — used by the error alert, aggregation builder, import and the delete/save dialogs
- **`useMongocampQuery`** (also `byId`/`byIds` — throw on a non-ObjectId, never `''` —, `isTrue`/`isFalse`, `arrayContains`, `hasItems` (= `exists`; `f:*` misses numeric arrays), `onDay`/`notOnDay` (whole UTC day), and `not`/`notAnd`/`notOr`: negated groups are rewritten with De Morgan because the server evaluates `-(A AND B)` as `-A AND -B`; parser in `utils/luceneExpression.ts`) — high-level Lucene query helpers (`equals`, `like`, `inRange`, `and`, `or`, …)
- **`useMongocampQueryBuilder`** — low-level Lucene syntax builder used by `useMongocampQuery`
- **`useMongocampExtendedJson`** — converts MongoDB extended-JSON documents to/from the plain values `FUAutoForm` binds to
- **`useMongocampPermissions`** — `canRead`/`canWrite`/`canAdminister(collection)` and `readableCollections(list)` from the session profile's grants (`utils/grantMatching.ts`: name matched exactly but case-insensitively, no wildcards, flags independent, only collection grants); UI-level and **fail-open** (admin, proxy mode, no grant list, GridFS bucket members ⇒ yes); `MongocampCollectionData` is read-only without `write`
- **`useMongocampExportAll`** — `exportCollection({ collection, format: 'json'|'ndjson'|'csv', filter, maxRows = 50 000, onProgress, signal, download })` over `useMongocampFetchAll`: file text from `utils/exportDocuments.ts` (`toExportRow`, `formatDocuments`, `exportColumns` = keys of all rows with `_id` first, `exportFilename`); an unsafe long is a BigInt → **bare number in JSON/NDJSON**, digits in CSV; `truncated` = the file is incomplete (still downloaded); abort rejects, nothing downloaded; also used by the data table's page export. The import wizard's JSON parser reads with `parseJsonKeepingLongs` and **refuses** a row with an integer beyond 2^53 (`unsafe-integer`) instead of silently rounding it
- **`useMongocampPersistedState`** — `useMongocampPersistedState(key | getter, defaults, { storage, version, migrate, validate })` → `{ state, reset }`: a ref backed by `localStorage` (`nuxt-ui-mongocamp:<key>`, `{ v, data }` envelope, merged over the defaults, 16 KB cap, every access in try/catch, `storage: null` = off, nothing on the server); pure part in `utils/persistedState.ts`. `MongocampCollectionData` remembers page size, sort and hidden columns per collection with it (`persistState`/`stateKey` props; a malformed entry is ignored field by field; filters are not remembered)
- **`useMongocampSavedQueries`** — `useMongocampSavedQueries(collection | getter)` → `saved`, `recent`, `save(name, query)`, `remove`, `record(query)`, `clearRecent`, `exportJson`/`importJson`: browser-only (over `useMongocampPersistedState`, key `savedQueries:<collection>`, 128 KB), a query is `{ filterGroup?, lucene?, sort?, projection? }`; max 50 saved (names unique case-insensitively) / 20 recent (deduped, ids and key order ignored); everything read from storage or an imported file is cleaned in `utils/savedQueries.ts` (unknown operator ⇒ the whole group dropped); `save`/`record` return a failure reason instead of throwing. No UI yet (plan 16)
- **`useMongocampAutoRefresh`** — `useMongocampAutoRefresh(load, { intervalMs, pauseWhenHidden = true, backoff })` → `start/stop/refreshNow`, `running`, `lastRefreshed`, `lastError`: a `setTimeout` chain (next wait starts after the load ended ⇒ no overlap), ≥ 1 s, ×2 backoff to 5 min (`utils/autoRefresh.ts` `nextDelay`), paused while `document.hidden`, load errors go to `lastError`, stops with the scope, no-op without `document`. `MongocampDashboard` and `MongocampJobs` take an opt-in `autoRefresh` prop (seconds); their background reload keeps the data on screen on failure
- **`useMongocampCollectionStats`** — `getStorage(collection)` (`getCollectionInformation` → `{ count, size, storageSize, avgObjSize, indexCount, indexSizes, totalIndexSize }`, bad numbers ⇒ 0, `ns` dropped) and `getIndexUsage(collection)` (`$indexStats` through `runAggregation(…, { allowStatsStages: true })` → `{ name, key, ops, since, unused }`; `host`/`ns`/`spec` never returned); mapping in `utils/collectionStats.ts`
- **`useMongocampCollectionCopy`** — `copyCollection({ source, target, filter, maxDocuments, signal, onProgress })` (count → cap refuse → read pages of 1 000 → `importRows` batches, `_id` kept, no metadata stamp; `refused`, `rows`, `failedBatches`, `aborted`/`skipped`, `totalChanged`), `backupCollection({ source, now?, onTarget? })` (same, target named by `backupName`, re-chosen up to 3× if taken; throws `CollectionNotCopyableError`), `retryBatches(target, rows, failed)`, `listCollectionNames`, `countDocuments`, `collectionCount`; `copyCollection`/`backupCollection` take `copyIndexes` → `indexes: { copied, skipped, failed }` / `indexesError`, `copyIndexes(source, target)` on its own; verified live: dates/longs/ids keep their types, 2 000 documents read back identical and the recreated indexes match
- **`useMongocampSavedPipelines`** — `useMongocampSavedPipelines(collection | getter)` → `saved`, `save(name, pipeline)`, `remove(name)`: `[{ name, pipeline: RequestStage[] }]` in `localStorage` (`savedPipelines:<collection>`), ≤ 50, 1–50 stages, ≤ 20 000 characters each; `utils/savedPipelines.ts` `sanitizePipeline` re-runs `findForbidden`, so a stored `$out`/`$function`/`$lookup` never comes back
- **`useMongocampServerOverview`** — `loadOverview({ maxCollections, concurrency, signal, onProgress })` → `{ databases | null, collections: CollectionStat[], collectionCount, skipped, failed, cluster | null, jobs | null, errors }` (pure helpers `rankCollections`/`overviewTotals`/`shareSlices`/`nextJobs` in `utils/serverOverview.ts`; `formatBytes` now lives in `utils/formatBytes.ts`, re-exported by `indexForm`)
- **`useMongocampFetchAll`** — `fetchAllDocuments(collection, { filter, sort, projection, … })` / `fetchAllFiles(bucket, …)` over `utils/pagedFetch.ts` `fetchAllPages`: sequential pages of 500 (the server honours far larger `rowsPerPage`; the page size is the speed lever), cap 10 000 rows by default (`truncated`), stops at the server's total (a short page is not the end), `onProgress`, abort **rejects** with `AbortError` (never a half-read list), `keyOf` drops rows repeated by skip/limit drift, `totalChanged`; rows read from the response text (exact longs)
- **`useMongocampRoles`** — `isAdmin`/`isManager` (admin always counts as manager) and `isAllowedPathForRoute(route)` (`notAllowedPath`, `logoutRedirectPath` and `loginPath` are always allowed), backing the runtime plugin's global auth middleware; reads the module's `nuxtUiMongocamp` options (`managerRoles`, `securedRouteParts`, `managementRouteParts`, `adminRouteParts`, `notAllowedPath`, `logoutRedirectPath`, `logoutPath`) from `useRuntimeConfig().public.nuxtUiMongocampOptions`
- **`useMongocampSession`** — `checkExpiry()` / `currentState()` (token `exp` only, no request; unreadable ⇒ `unknown`, never expired), `verify()` (one `isAuthenticated` request: only a readable 401/`false` is `invalid`, everything else `unknown`; used by the opt-in `sessionGuardVerify` option, cached 30 s per token via `createVerifyCache`, client only), and `invalidateSession()`; everything `unknown`/no-op in proxy mode. Pure helpers: `utils/jwtExpiry.ts`, `sessionGuard.ts`
- **`useMongocampClientApi`** — the drop-in every other composable/component calls instead of the dependency's `useMongocampApi()`; switches between session mode and `useMongocampProxyApi()` based on `useServerProxy`; both install `utils/permissionDenied.ts`'s middleware, which turns the server's missing-grant `401` (code 4011, `user not authorized for …`) into a `403` — otherwise the dependency clears the session on any 401 and a non-admin who hits one forbidden request is logged out (a dead token, plain `user not authorized`, stays a 401)
- **`useMongocampProxyApi`** — session-mode-shaped API client (`adminApi`, `documentApi`, ...) pointed at the local server proxy route instead of the real MongoCamp URL; builds the 11 API classes itself via `src/runtime/utils/createProxyMongocampApis.ts`, since the dependency's own `createMongocampApis` factory isn't part of its public export surface

**Document paths** — `utils/documentPaths.ts` (no UI yet; for the viewer/compare/column picker of plan 16): `flattenDocument(doc, { maxDepth 32, maxEntries 10 000, inferStrings })` → `{ entries: [{ path, type, value }], truncated }` (arrays by index, a `{ $oid }`/`{ $date }`/`{ $numberLong }` wrapper is one leaf, an empty container is a leaf), `typeOf`, `getPath`/`hasPath`/`setPath` (copy, never mutates; refuses `__proto__`/`constructor`/`prototype`, never reads inherited keys); a key with `.` or `\` is written `a\.b`. Plain documents have no wrappers (`_id`, dates are strings), so `inferStrings` guesses 24-hex ⇒ objectId and full ISO timestamps ⇒ date.

**Auto-import surface:** the whole `src/runtime/composables/` directory is registered with `addImportsDir`, so *every named export there becomes a global in consumer apps*. Keep exports to `use*` functions (types are fine) and put pure helpers in `src/runtime/utils/` (not scanned; imported relatively) — e.g. `utils/filterBuilder.ts`, `bulkDelete.ts`, `exportRows.ts`, `escapeFieldName.ts`, `isoDate.ts`, `createSelectColumn.ts`, `collectionProtection.ts`, `jwtExpiry.ts`, `configRows.ts`, `sessionGuard.ts`, `importRows.ts`, `importPipeline.ts`, `batchInsert.ts`, `bulkEdit.ts`, `objectId.ts`, `aggregationPipeline.ts`, `aggregationErrors.ts`, `aggregationResult.ts`, `analyzeSamples.ts`, `filterSuggestions.ts`; the matching composables just return them. (`unwrapExtendedJson`/`wrapExtendedJson` predate this rule and stay exported.) Check with `grep "src/runtime/composables" playground/.nuxt/types/imports.d.ts`.

### Internationalization — `src/runtime/locales/`

`@nuxtjs/i18n` is a `moduleDependency` (registered unconditionally, like `@nuxt/ui`) so every consumer app gets it whether or not they use i18n themselves. Every user-facing string in this module's own components/composables goes through `useI18n()`'s `t()`, keyed under a single top-level `nuxtUiMongocamp` namespace (e.g. `t('nuxtUiMongocamp.login.heading')`) — this avoids colliding with a consumer app's own translation keys, which live in their own namespaces.

- `en.json` (default) and `de.json` live in `src/runtime/locales/` and ship inside the published package.
- Registered via `nuxt.hook('i18n:registerModule', ...)` in `src/module.ts`'s `setup()`, **not** via `moduleDependencies['@nuxtjs/i18n'].defaults` — `@nuxtjs/i18n` reads `nuxt.options.i18n` during its own module setup, which runs *before* this module's `setup()` (moduleDependencies install first), so mutating `nuxt.options.i18n` directly is too late for `locales`/`langDir`. `i18n:registerModule` is the hook `@nuxtjs/i18n` exposes specifically for other modules to contribute locale files into its merged registry, independent of setup order. Flat, top-level options like `defaultLocale` merge fine through `moduleDependencies[...].defaults`, though.
- Adding a new component string: add the key to *both* `en.json` and `de.json` under `nuxtUiMongocamp.<component>.<key>`, then reference it via `t('nuxtUiMongocamp.<component>.<key>')`. Keep the English value identical to what it replaces — component/unit tests assert against rendered English text under the default locale, so a mismatched value breaks them even though the app still runs fine.
- Composables that show toasts (`useMongocampBucket`, `useMongocampAccount`) call `useI18n()` themselves; components layer their own `t()` on top for template/schema strings. Table `columns` are a `computed()` (the static-string `header: t(...)` entries need it), so headers re-translate live when the locale changes without a remount — keep new static column arrays `computed` too. `MongocampCollectionData`'s columns are derived from data keys, not translated, so they stay a `ref`.
- **Never put a literal `{`/`}` (or `@`, `|` outside a plural) in a locale string** — vue-i18n reads braces as a placeholder, and one bad string makes the *whole* locale fail to load (every component test then fails with `Failed to load messages for locale "en" … Invalid token in placeholder`). Put JSON/code examples in the component as a constant, or reword.
- Unit tests that mock `#imports` entirely (see `useMongocampAccount.test.ts`, `useMongocampBucket.test.ts`) need `useI18n: () => ({ t: (key: string) => key })` in the mock, or the composable throws immediately on the first `t()` call.

### FormKit / @sfxcode/nuxt-ui-formkit conventions

Forms use FormKit schema arrays (not template markup). The key custom input types are `nuxtUIInput`, `nuxtUISwitch`, `nuxtUIListbox`, and `nuxtUISelectMenu` — all provided by `@sfxcode/nuxt-ui-formkit`. The `FUDataEdit` component wraps schema + submit logic. See `playground/formkit.config.ts` for how inputs are registered.

Listbox in transfer mode requires `displayMode: 'transfer'` and options as `{ value, label }` objects. SelectMenu options can be plain strings. Use `options` (not `items`) as the schema key for both `nuxtUIListbox` and `nuxtUISelectMenu` — set it directly on the schema node object. Inputs are bulk-registered via `nuxtUIInputs` and `nuxtUIOutputs` spreads from `@sfxcode/nuxt-ui-formkit/definitions` — see `playground/formkit.config.ts`.

### Playground — `playground/`

SSR is disabled (`ssr: false`). The playground registers the module directly via the local import (`import NuxtUIMongocamp from '..'`). Its `nuxt.config.ts` sets `nuxtUiMongocamp: { useGlobalAuthMiddleware: true, securedRouteParts: ['/secured/**'], managementRouteParts: ['/secured/manager/**'], adminRouteParts: ['/secured/admin/**'], managerRoles: ['manager'] }` so pages under `/secured/`, `/secured/manager/`, and `/secured/admin/` are protected — this is opt-in and not automatic for consumers of the module. The `mongocamp` config key in `nuxt.config.ts` passes through to `@sfxcode/nuxt-mongocamp-server`. Collection and bucket pages use the playground's `collection` layout (sidebar `CollectionSidebar`, tabs `CollectionTabs`, palette) — the reference "admin shell"; plan 16 phase 13 decided **not** to ship a shell component (see `docs/guide/admin-app.md`).

### Tests — `test/`

`vitest.config.ts` defines three projects. `pnpm run test` explicitly runs only the first two (`--project unit --project components`) — a bare `vitest run` would otherwise also sweep in `e2e-auth`, which needs Playwright browsers that aren't installed in CI:
- **`unit`** — `test/*.test.ts`, plain Node environment, composables mocked via `vi.mock` (relative-path imports) or by faking `#imports` entirely — see `brain/patterns/testing-nuxt-auto-import-composables.md`. E2e smoke coverage lives here too (`test/basic.test.ts`, via `@nuxt/test-utils/e2e`'s `setup()`+`$fetch`).
- **`components`** — `test/components/**/*.test.ts`, a real booted Nuxt environment (`happy-dom`, via `@nuxt/test-utils/runtime`'s `mountSuspended`) against the `test/fixtures/basic/` fixture (which also needs a `pages/` dir and `formkit.config.ts` for this to work — see `brain/patterns/component-testing-nuxt-environment.md` for the full list of gotchas: `UApp` wrapper, teleported `UModal` content, FormKit id/validation timing).
- **`e2e-auth`** — `test/e2e-auth/**/*.test.ts`, real-browser (Playwright, via `@nuxt/test-utils/e2e`'s `createPage`) coverage for the global auth/role middleware. Run manually with `pnpm run test:e2e:auth` after a one-time `npx playwright install chromium` — deliberately **not** part of `pnpm run test`/CI, since Playwright needs installed browser binaries. The session is seeded as the `mongocamp-session` **cookie** (`test/fixtures/auth/e2e-helpers.ts`); the suite was last run green (21/21, incl. `session-guard.test.ts`) on 2026-10-21. A Playwright upgrade can require `pnpm exec playwright install chromium` again. See `brain/patterns/e2e-browser-testing.md`.

Run a single test file with `pnpm vitest run test/basic.test.ts` or `pnpm vitest run --project components test/components/MongocampRoles.test.ts`.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>
```

Common types: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`, `style`.  
Scope is optional but useful (e.g. `feat(users)`, `fix(plugin)`, `docs(readme)`).

Examples:
```
feat(roles): add collection grant management to MongocampRoles
fix(plugin): redirect to / instead of /secured on logout
docs: add CLAUDE.md with architecture overview
chore: bump @nuxt/ui to 4.9.0
```
